# Overlay director channel-40 output batch

This corrected source-only delta is based on B5 commit `9cbefd173085312ebaee5bab4875b8492fc292cb` and physical parent HEAD `cc54c12ebfaaadfc9b6cec42393b19355f05b595`. The private documentation/workflow commit is `9a100da7c0e7963a5d0962b8bb308f781da23e44`. The earlier reuse-only proposal remains preserved in [`codex02_9cbefd`](../gui_debug_overlay_director_batch_20261023_codex02_9cbefd); the five-call packet is preserved in [`codex01`](../gui_debug_event_publish_batch_20261023_codex01). The full postimages are read from B5 `9cbefd` and retain its committed CrashNavSettings event-191 repair.

The patch changes two raw generic-publisher call sites and repairs one TU-local wire helper used by a third producer. All three feed the same OverlayDirector input path. It leaves the shared `OutputGuiEvent<T>` template and decoder alone.

- `CrashNavSettings::OnInputSponsorProductCode` already uses `GuiOverlayRequestWire184` for the `CNSpnsrUnlkF` request. In the base, that helper puts the 288-byte request at `+0x0C`, but its header declares offset `16` and its record is only 300 bytes. ARTIST `0x824CD030` builds `{288,184,16}+288` and queues 304 bytes on channel 40. The patch adds explicit padding at `+0x0C`, with size and offset assertions; this existing sponsor post then matches the original record.
- `CrashNavSettings::HandleControllerInput` posts the `PRONoSaveLd` overlay when a signed-out user selects Profile. ARTIST `0x824D90E8` calls `OutputGuiEvent<GuiOverlayRequest>`; publisher `0x82436BE0` writes the same `{288,184,16}+288`, 304-byte channel-40 record. The caller now fills and queues the corrected wire helper directly.
- `RaceMainHudState::UpdatePermenant` posts `GuiOverlayWaitFinishRequest` from the pre-event overlay expiry branch. The source explicitly says this branch is only reachable under the debug component-override table. ARTIST `0x824806E8` calls `OutputGuiEvent<GuiOverlayWaitFinishRequest>`; publisher `0x82476E98` writes `{8,188,16}+8` and queues 24 bytes on channel 40. The proposal reuses `GuiOverlayWaitFinishWire`, which the same TU already uses for the `OnLeave` post.

The 9cbefd-wide GUI source scan found 23 TU-local event-184 wire-helper definitions: 22 already have an explicit word before the request, and only `CrashNavSettings.cpp::GuiOverlayRequestWire184` lacked it. The malformed helper has one existing producer (the sponsor no-match prompt); the delta also routes the Profile prompt through it. That is two affected event-184 producer sites, plus the separate event-188 site—not 23 affected posts.

The generic PC body queues the Profile and pre-event posts under direct IDs 184/188, which the flow-output drain does not accept; the channel-40 wrapper route already feeds `mGuiOutQueue` and the OverlayDirector loopback. The sponsor post is already on channel 40, but its base helper's header offset and 300-byte record disagree: the drain reads from `+0x10` although the helper places the request at `+0x0C`, and 16+288 exceeds the 300-byte record. After the pad, both overlay-request producers send the original 304-byte shape, and event 188 sends the original 24-byte shape. Existing `BrnOnlineInstantResults.cpp` requests already use a channel-40 helper and are outside this delta.

DecFIGS supplies the declaration shape: `GuiOverlayRequest` has its overlay id and message/button parameter storage; `GuiOverlayWaitFinishRequest` carries a CgsID. DecFIGS uses earlier event IDs 182/186 for these types; ARTIST owns the target IDs 184/188 and the wire sizes/offsets used here. The DWARF wrappers in `CgsGuiStateInterface.h` independently show that both `OutputGuiEvent<T>` instantiations use channel-40 `GuiEventWrapper` records.

The corrected delta modifies the local `GuiOverlayRequestWire184`, routes the Profile post through it, and routes the debug-gated event-188 post through the already-correct `GuiOverlayWaitFinishWire`. Its three affected producers are mapped in [site_map.tsv](site_map.tsv). The exact diff from `9cbefd` is in [proposal.patch](proposal.patch), with full source postimages under [composed_postimage](composed_postimage/) and ARTIST/DecFIGS bindings in [bindings.json](bindings.json). No production files, shared decoder, refs, index, or campaign inventory were changed. No compile, test, CI, native/game, Stage, Run, or input action was performed; this is source-only evidence.
