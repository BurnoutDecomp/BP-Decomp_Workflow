## Behavioral bindings

- ARTIST `BrnGui::GuiModule::PreWorldUpdate` at `0x8251A3D0` is the behavioral source for the override. It starts the `GUI MODULE PRE-WORLD UPDATE` monitor, asserts the four inputs, write-locks GUI output, runs collision validation then car-pool validation then `ProfileManager::LoadProfileUpgradeData`, unlocks, publishes any pending video-data acquire (type 4, event id `0x1AFFEED`, pool 11), calls the shared GUI base `PreWorldUpdate`, then stops the monitor. The existing `PublishNativeMovieResourceRequest` helper already matches the acquire block and owns its second lock interval.
- ARTIST `UpdateCollisionWorldValidation` at `0x82519578` is a 13-state switch. The packet restores every state/value from DecFIGS and retains the original split between boot/save-load swap requests (GameData request types 67/68) and movie/network GUI events (493). Boot swap-out replies store the collision resource/descriptor through the existing `MovieManager::FreeCollisionPoolMemory`; save/load state transitions use the existing `ProfileManager` collision methods.
- ARTIST `UpdateCarPoolValidation` at `0x82514228` is a six-state switch. Its typed pool requests use traffic pool 15 and request event types 7/8. It preserves the `IN_USE` retry, `SetCarPoolValid` resource/descriptor transfers, the one-byte game action 13, and the exact neutral three-pool descriptor written on completion. `mbTrafficPoolEmptied` has no explicit ARTIST Construct store; this proposal does not add one.
- ARTIST `GuiModule::Construct` at `0x82518028` owns the new enum seeds, invalid=false seed (ARTIST register/store chain; original pseudocode disagrees), two networking-latch clears, and the 1024/16 collision receiver construction. The event receiver and GameData receiver remain the existing current-c1 owners. The receiver member deliberately keeps DecFIGS's original spelling `mCollisonPoolValidationReceiverQueue`.
- ARTIST `GuiModule::Update` at `0x82527A58` distinguishes input event 493 values 2/3 (world collision invalidated/validated) from output request values 0/1, and consumes event 512 as the one-byte traffic-pool empty/refill latch. The packet restores those two input consumer arms in the existing c1 `DispatchInboundGuiEvents` switch.

DecFIGS `BrnGuiModule.h` lines 332-358 supplies the enum values; lines 401-426 and 537-547 supply the field names/types; lines 643, 737, and 740 establish the virtual `PreWorldUpdate` and the two helper signatures. ARTIST pseudocode and assembly are kept in `evidence/artist/*.json`.

## Current-source boundaries and dependencies

The exact c1 world bridge already consumes GUI output event 493 and converts values 0/1 into world collision requests. The c1 world-to-GUI bridge already forwards traffic event 512. Its `BridgeWorldToGui` umbrella still has the collision completion producer marked deferred; the values 2/3 needed by the newly restored input consumer have no current c1 producer.

The source also lacks ARTIST `GuiModule::HandleEventsPostBaseModuleUpdate` at `0x82507800`. That original post-base handler consumes the output-side 493 request events and sets `mbCollisionWorldInvalidateForNetworking` / `mbCollisionWorldValidateForNetworking`; the new validator preserves those latches and their consume-and-clear behavior, but this packet does not add or call the missing post-base handler. Current c1 GUI `Update` is a selected PC overload and has no typed output-buffer hook for that original handler. Networking transitions therefore remain an explicit dependency.

Current c1 `GuiModule::Update` also polls the profile manager's pending collision invalidation/validation and directly marks the profile collision state valid/invalid in its flagged PC path (around `BrnGuiModule.cpp:3463-3471`). If the native PreWorld override is selected later, that stand-in must be reconciled so the same pending profile request is not consumed twice. `BrnGameModule::DoUpdate_GuiPreWorld` exists in c1 as a dormant helper, but active GameMain does not call it. This packet does not alter GameMain or claim that the override runs.

`evidence/c1_source_contracts.md` contains exact-c1 blob ids, SHA-256 digests, physical line excerpts for the queue/API owners, profile/movie methods, existing 493/512 bridges, and the dormant frame helper. The new body follows named types and queues; it adds no member-offset casts or synthetic platform APIs.
