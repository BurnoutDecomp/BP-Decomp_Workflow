# Original schema registration and builtin owner

This proposal recovers original GameDataModule::PrepareAttribSysSchemaResource with both caller-owned IO stacks and the real Attrib input. It also supplies the canonical schema declarations and exact original X360 builtin VLT/BIN data definitions. The retained native schema helper and active two-argument Prepare remain byte-identical.

Four source paths are proposed. The existing GameData CPP preimage is exact source2ce plus the sealed seventh packet; `SOURCE_MANIFEST.json` binds that full overlay and every pre/post image. The three schema owner files are absent from source2ce and new in the proposal. Declaration names/shape come from DecFIGS BrnAttribSchema.h; the X360 provider subfolder and filename spelling are chosen organization, not a claim that the stripped target retains those original filenames.

The caller's original three stages are complete. Stage0 locks Attrib input and submits RegisterSchema with the real global arrays/sizes, unlocks, clears the receiver and stores1. Stage1 accepts positive receiver length, clears and stores2, but still pumps that invocation. Only a later entry at2 returns true. Pending and invalid stages unlock/pump/destroy Resource input, process actual Attrib inputs, then return false. Every entry, including stage2, creates and write-locks its actual Resource input first. There is no file fallback, loaded-flag skip, synthetic response or new result/type check.

The primary instruction pairs resolve VLT to82CD3D88,5664bytes, SHA256 `93190b2d679a18c0974dc6d720162a8ddb8930e982cbfa827e969b5608a7559f`, and BIN to82CD53B0,20352bytes, SHA256 `d55b848e894b2ce099b6d9401150c2ef16bf810352389615a76c3a5c91a9cbdd`. BIN53AC is a preceding u32=1, excluded from the provider. All generated C++ char-array bytes independently roundtrip to the exact selected primary windows.

The first bounded data probe retained the old comment's53AC address and exposed that prefix; its raw receipt remains as evidence of the corrected assumption. A second bounded read decoded the actual lis/addi instruction bytes and read the true caller arrays. Only the `_from_caller.bin` files generate source. The existing port tool's53B0 extraction agrees with the instruction bytes; comments in older native source do not govern the provider.

These are exact BE X360 providers, supplied without shipping mounts or activation. The current PC schema port produces LE loose files for the retained native path. Choosing a native compiled provider or an equivalent reviewed PC data leaf remains a platform integration decision; feeding these BE arrays to the current LE runtime is not approved. No converter, runtime, asset, flag or allocation policy changes here. The new data CPPs are explicitly absent from the shipping source list, and that is recorded rather than claimed link-ready.

The full sixth Resource update/destructor overlay, its separate setter correction, and the seventh list helpers remain named prerequisites. Root owns the separately reviewed include correction. One original GameData helper body remains: VehicleList with its genuine ResourcePtr/Entry diagnostic stream dependencies. Original Construct/factories, native memory capacities, sky-dome/thread reuse, error callback wiring and renderer activation remain separate.
