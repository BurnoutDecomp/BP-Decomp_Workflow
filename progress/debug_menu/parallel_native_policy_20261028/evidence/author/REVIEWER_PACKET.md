# Configurable parallel harness (workflow only)

Baseline workflow: `54a7fd30253542a9b001923b4aad206a33b4e379`. Proposed changes are in `post/`; exact baseline bytes are in `pre/`. No shared source, Git refs, game, profile, or runtime bindings were modified.

The existing private strict opt-in accepts exactly one other game. This makes a human-authorized larger swarm refuse before profile setup or launch, even when every stage has its own executable. Both script entry points now expose `[ValidateRange(1,100)][int]$MaxConcurrentOtherGames = 1`. A case can set `Run.MaxConcurrentOtherGames`; an explicit runner CLI argument takes precedence and the effective value is forwarded to `flow_run.ps1`. Values above 1 require `AllowConcurrentGames`; the existing StrictGameOwnership, positive Slot, resolved private sibling slot/data checks still apply to every active run. Range 1..100 retains the existing default and avoids introducing a second way to disable concurrency (omit AllowConcurrentGames to require exclusive strict ownership).

Example: a case Run has `StrictGameOwnership=$true; AllowConcurrentGames=$true; MaxConcurrentOtherGames=100`; call `run_case.ps1 -Case <case> -Slot <positive> -GameDir <stage>\slot -WorkingDirectory <stage>\data`. Direct flow CLI uses the equivalent switches and `-MaxConcurrentOtherGames 100`. The cap counts other processes, so cap100 allows up to 101 games including this run; a 100-game swarm can choose 99 or 100. Each process must have a unique normalized executable image. The case CLI can override a case cap without rewriting it. Both terminal JSON outputs record the configured cap.

The count comparison lives inside the existing opt-in helper paths only. The case helper runs before profile mutation and after flow before profile restoration; the flow helper runs at early setup, immediately before launch, and during the monitor with only the owned PID excluded. Every existing call and argument is unchanged. NoKill/NoLock bypass or global process termination was added. Per-slot locking, owned creation handle/PID/image/start-time cleanup, fixture/profile parking and restore guards, and input reset remain unchanged. Two foreign processes resolving to the same normalized, case-insensitive executable now explicitly reject at every helper phase; default cap1 previously rejected this roster by count.
