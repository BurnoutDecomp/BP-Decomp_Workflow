# GUI stored-inbox restore proposal (source only)

This candidate restores the missing next-update handoff for the active PC GUI module output while preserving the current same-step game bridges. It is bound to b5 source commit `edca934dc502f71f64ad873cdd386afe5e3eeeb2`; the exact before/after images and unified source patch are under `source/`.

The candidate reuses inherited `CgsGui::GuiModule::mStoredGuiEvents`. At the start of the typed GUI update it appends the previous stored records after records already in this substep's caller-owned GUI input queue, then clears the persistent queue. At the end it stores the complete canonical `mGuiOutQueue`; the ViewIO event queue is appended immediately before its persistent PC stand-in is cleared. The existing `BridgeFromViewToOutput` helper now appends the custom-renderer output queue and the view module's own output queue in ARTIST order.

Observer delivery moves to the existing module-input tail. Channel-40 flow records, profile-manager records, custom-renderer output, and ViewIO events are no longer fanned out as immediate PC side paths. The same-step `mGuiOutQueue` source remains intact for the existing game, sound, and director bridges; the frame owner still copies it to `mpGuiOutputBuffer` and clears it only after those consumers. The seven-ID `mOverlayLoopBackQueue` field and late append are removed, so the analyzer, normal input handlers, flows, and overlays director observe the same stored batch in their established order.

The input dispatch now handles events 507 and 22 from the returned batch. Event 507 calls the existing `UpdatePlayerName`. Event 22 resolves its movie name from the layer and calls the existing `FlaptSoundTriggerCallback`, which produces typed output 201. This replaces both old immediate event-22 conversions (channel-40 drain and ViewIO end-of-frame) with one next-update path.

The existing input case 356 remains the autosave latch. Its late channel-40 drain shortcut is removed: the record is stored after frame N and consumed by case 356 before the autosave tail on frame N+1. Event 144 similarly reaches the existing RunFsm input arm on the next update; case 141 creates response 142 in the same update's output. These replacements keep each event's observer delivery and module-input handling on one path.

This proposal deliberately does not fold the ModelIO load-notification queue into the new batch. ARTIST `BridgeFromModelToOutput` also stores ModelIO notifications, but the selected PC path currently has a separate resource-module route into ModelOutput and ViewInput, followed by direct cache/renderer consumption and queue clearing. Copying those same records into this batch without moving that whole consumer chain would duplicate them. That ModelIO bridge remains a separate recovery boundary; this packet claims the module output plus ViewIO-event sources described above, not every source in the native base class.

`evidence/artist/` contains the complete raw ARTIST exports (pseudocode and assembly) for the original GUI owner, event interpreter, and frame callers. `evidence/decfigs/CgsGuiModule.h` pins the inherited member name/type. `evidence/pc_base/` contains exact source snapshots from the bound base commit. `evidence/source_hashes.tsv` binds copied evidence. No production file, Git ref/index, build, test, CI, native run, or game input was changed or run for this proposal. Root owns composition and hosted validation.
