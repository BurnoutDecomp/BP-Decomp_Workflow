# Explicit ModelIO boundary

ARTIST `CgsGui::GuiModule::BridgeFromModelToOutput @0x8285DD40` has three effects: carry a non-empty resource-request queue to module output, append `ModelIO::GetGuiOutEvents()` to module output, and append `ModelIO::GetLoadNotifications()` to `mStoredGuiEvents`. ARTIST `BridgeFromViewToOutput` separately appends ViewIO events to the stored queue, then custom-renderer and ViewModule outputs to module output. The raw target exports and the current `CgsGuiModuleBridges.cpp` source snapshot are included in the packet.

The selected PC `BrnGui::GuiModule::Update()` does not call the inherited `CgsGui::GuiModule::Update()`. Its current resource path instead runs `DispatchGuiResourceModule`, adds resource notifications directly to `mModelOutputBuffer`, conditionally to `mViewInputBuffer`, feeds the cache/renderer/model controller, and clears those buffers in the same update. Folding those ModelIO notifications into the new stored inbox without moving that separate pipeline would re-present the same completion to current and next-update consumers. For this reason the candidate restores active `mGuiOutQueue` and ViewIO event sources only. Full parity of ModelIO `GuiOutEvents`, resource requests, and load notifications remains an explicit follow-on boundary.
